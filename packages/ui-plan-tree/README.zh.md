# @t4r71/dsh-ui-plan-tree

[English](README.md) | 中文

## 概述

右侧边栏的计划页签类型：把会话已声明的计划绘制成一棵嵌套的步骤树，每个节点一行，各带自己的状态图标。它是从引导页进入的页面类型，不占用任何地址；它读取宿主已经折叠好的 `planTree` 投影并且不做任何写入——计划属于模型的 `plan_write` 与 `plan_step` 调用。

<a id="what-it-registers"></a>
## 注册了什么

- **类型** —— `ctx.sidebarRightTabs.register(...)`，kind 为 `plan-tree`，id 为 `@t4r71/dsh-ui-plan-tree`，band 为 `builtin`，无 pattern，并有一条引导项（顺序 20，标题与描述取自 `planTree` 命名空间，图标为共享的计划图标）用于打开该类型。
- **主体** —— 该 id 下带键的 `sidebar.right.pane.tab` 座位：先是一行概要（类型名与进度），然后是树。概要会统计树中每一个节点，因此父节点自身的状态与其子节点的状态都会被计入。
- **标签标题** —— 该 id 下带键的 `sidebar.right.pane.tab.title` 座位：类型标签之前 14px 的共享计划图标。

`src/client/` 下六个源文件：`definition.tsx`（类型）、`PlanTreePanel.tsx`（绘制内容，含四个状态图标与计数辅助函数）、`PlanTreePanel.module.css`（外观）、`locales.ts`（文案）、`index.ts`（接线），另有共享的 `css-modules.d.ts` 声明。

<a id="the-panel"></a>
## 面板

屏幕上的所有内容都经由会话标准套件的 `useProjection('planTree')` 到达；面板自身不做折叠，除了读者展开过哪些节点之外不持有任何状态。

| 投影值 | 面板 |
|---|---|
| `undefined` | 什么都不画——宿主半边未加载，该能力在此不存在。 |
| `null` | 什么都不画——本会话尚未声明任何计划。 |
| `[]` | 什么都不画——已声明但没有步骤的计划。 |
| `PlanNode[]` | 概要行与树。 |

带子节点的节点渲染为携带 `aria-expanded` 的展开按钮，初始为收起，因此深层的计划会先停在顶层；叶子节点渲染为纯标记。每一行的 data 属性携带其状态，图标则以形状表达同一件事：`pending` 是虚线圆环，`in_progress` 是旋转的渐变圆环，`completed` 是带镂空对勾的实心圆盘，`blocked` 是带叉的圆环。

概要只拼接非零计数——已完成（只要存在任何节点就会显示）、进行中、受阻、待办——因此还没有任何步骤完成的计划也会用一段来报出进度，而不是保持沉默。四个状态图标是内联 SVG：共享图标集中没有与状态刻度相匹配的轮廓，它们各自携带自己的墨色 token。

<a id="model-experience"></a>
## 模型体验

### 在浏览器中绘制的计划状态

#### 模型看到什么

什么都不看到。本包不注册任何工具、任何提示词段落、任何会话事件；它读取的是宿主的 `plan_write` 与 `plan_step` 工具已经折叠好的 `planTree` 投影。面板计算出的任何东西——展开集合、计数、某个状态画出的图标——都不会回到请求中。

#### Token 影响

无。面板是浏览器产物，它消费的投影从不进入模型请求；计划唯一消耗的 token 是声明并推进它的那几次工具调用，由宿主包计费。

#### KV Cache 影响

无。由于这里没有任何东西被组装进请求，打开页签、展开节点或切换会话都会让请求前缀保持逐字节一致。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>
- **只读。** 面板只绘制计划，从不编辑它：没有状态切换、没有重命名、没有增删。变更某个步骤意味着向模型提出请求，其工具调用是唯一的写入方。
- **展开状态随挂载存亡。** 已展开节点的集合是组件状态，因此切到另一个边栏页签再切回来会把树重置回顶层；没有任何持久化或恢复。
- **每个会话一个面板。** 面板跟随它被打开时所属的会话；没有跨会话或多计划视图，也无法把一个计划固定在另一个旁边。
- **没有搜索或过滤。** 已声明的每个节点都会被绘制，无论其状态如何；大型计划只能通过滚动与展开来浏览。
